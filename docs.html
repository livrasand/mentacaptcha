Self-Hosting

Menta is designed to run on your own server, VPS, or edge host. You keep the data, the keys, and the logs — no third-party service sits in the path.

1. Requirements

  • Python 3.8 or newer
  • A TLS-terminating reverse proxy (nginx, Caddy, or your platform's load balancer) for production

2. Install

git clone https://github.com/livrasand/mentacaptcha
cd mentacaptcha
pip install -r requirements.txt

3. Configure

Create a .env file in the project root. All settings are optional — sensible privacy-safe defaults apply when they are omitted.

DB_PATH=/var/lib/menta/menta.db
DB_ENCRYPTION_KEY=replace-with-a-strong-passphrase
CORS_ORIGINS=https://app.example.com
TRUSTED_PROXIES=127.0.0.1
DATA_RETENTION_HOURS=24
LOG_IP_FULL=false
VariablePurposeDefault
DB_PATHLocation of the SQLite/SQLCipher databasementa.db
DB_ENCRYPTION_KEYEncrypts data at rest via SQLCipher. When set and sqlcipher3 is installed, the database is encrypted; otherwise it falls back to plain SQLite.empty (plain)
CORS_ORIGINSComma-separated list of origins allowed to call the APIstrict
TRUSTED_PROXIESProxy addresses/CIDRs whose X-Forwarded-For headers are trustedempty
DATA_RETENTION_HOURSHow long challenge data is retained before cleanup24
LOG_IP_FULLStore full IPs instead of anonymized /24 (IPv4) or /64 (IPv6) prefixesfalse

4. Run

For local development:

python app.py   # serves on http://localhost:5000

For production, run the Flask app behind a WSGI server (gunicorn, waitress, or uWSGI) on your own host and terminate TLS at your reverse proxy. Set CORS_ORIGINS to the exact origins permitted to load the widget and TRUSTED_PROXIES to your proxy so client IPs are resolved correctly.

Then point the widget at your instance — see Quick Start below, using your own domain as data-cap-api-endpoint.

How Menta Works (flow)

  1. Init — POST /init with Origin. Server validates browser signals, rate limits and bot_shield; creates signed session tied to IP prefix.
  2. Challenge — POST /challenge with session_id + signature. Server validates session (exists, not expired, IP match, HMAC, min solve time), then issues salt + adaptive difficulty.
  3. Solve — client brute-forces a nonce such that SHA-256(salt + nonce) starts with N zero hex chars (typically 1-3s).
  4. Redeem — POST solution to /redeem. Server verifies PoW, nonce entropy, client pattern, issues single-use JWT (jti).
  5. Verify — backend POSTs token to /verify; server validates signature/expiry, consumes jti, returns valid/invalid.

No cookies, no localStorage, no third-party telemetry. State lives in memory only.

Blocking mechanisms

  • bot_shield — classifies UA (known bots, generic scripts), verifies bot IP via IP ranges / reverse-DNS, checks robots.txt, JA3/JA4 TLS fingerprint mismatch. Actions: allow / block (403) / shield (max-difficulty PoW).
  • Rate limits — per IP, per tenant, global, for /init, /challenge, /redeem, /verify, /shield/*.
  • Browser signals — validates Origin and basic browser characteristics (no fingerprinting).
  • Session validity — existence, expiry, IP prefix match, HMAC signature, min solve time (0.5s init, 1s redeem).
  • Nonce entropy — rejects precomputed/reused nonces.
  • Client pattern — solve time analyzed against human range.
  • Token single-use — consumed on /verify via jti (DB unique constraint).

Shield mode (/shield/check, /shield/redeem, /shield/verify) applies the same logic without widget or domain registration.

Adaptive difficulty algorithm

target = base_difficulty(ip_reputation)
if new_ip:            target += 1        # higher until reputation established
if fast_solve:        target += 1        # possible bot
if many_failures:     target += 2        # significant increase
if consistent_pattern: target += 1        # possible automation
if shielded:          target = max(target, MAX_DIFFICULTY)
# PoW: find nonce where SHA-256(salt + nonce).startswith(target zeros)

Data processing & privacy

  • IP anonymization — only /24 (IPv4) or /64 (IPv6) prefix used by default; full IP only if LOG_IP_FULL=true.
  • Analytics pseudonym — raw IP never persisted; HMAC-SHA256 truncated (32 hex) with ANALYTICS_IP_SALT (falls back to SECRET_KEY). Visitors shown as anon-<hash>.
  • GeoIP — optional MaxMind GeoLite2 City, resolved in memory; only country/region/city stored. Without it, reports Unknown.
  • Referrers — reduced to host/origin, dropping query strings.
  • Retention — expired challenges/sessions/tokens cleaned via DATA_RETENTION_HOURS (default 24h); analytics via ANALYTICS_RETENTION_HOURS.
  • Encryption — SQLCipher at rest (DB_ENCRYPTION_KEY) + TLS in transit.
  • Rights — /admin/export-data and /admin/delete-data for data subject requests.

Analytics views at /admin/analytics require authenticated admin session with 2FA; results scoped to tenant.

Quick Start

Add Menta to your page in two lines:

<script src="https://your-domain.com/menta-captcha.js"></script>
<menta-widget data-cap-api-endpoint="https://your-domain.com"></menta-widget>

The widget automatically initializes and handles the challenge flow.

Theme

Set data-cap-theme to control appearance:

  • light — Default light theme
  • dark — Dark theme
  • auto — Follows OS preference

POST /verify
Content-Type: application/json

{
  "token": "eyJhbGciOiJIUzI1NiIs..."
}

Response:
{
  "valid": true,
  "tenant_id": "your-tenant"
}

Menta Shield (drop-in page protection)

Protect any page without a widget or domain registration:

<script src="https://your-domain.com/menta-challenge.js" data-menta-api="https://your-domain.com" data-menta-next="/protected"></script>
  • data-menta-api — Menta instance URL (defaults to current origin)
  • data-menta-next — redirect target after success (defaults to current path)
  • data-menta-i18n-checking — custom checking message

Or link directly to the interstitial page: /challenge-page?next=/protected

Admin Dashboard

Open /dashboard and authenticate with ADMIN_TOKEN (and TOTP if configured). Features:

  • Metrics by time range (1h / 24h / 7d / all) and all-time totals
  • Top offending IPs for blocking
  • Create/delete accounts and domains
  • Data subject requests: export or delete data by IP/prefix
  • Admin 2FA setup and recovery codes

Admin session can be remembered for 30 days via localStorage (Menta's own dashboard only).
